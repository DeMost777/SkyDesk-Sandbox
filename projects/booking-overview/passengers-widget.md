# Flow: виджет Passengers

> Flow doc. Read it before the code; update it in the same change as the behavior.
> Updated: 2026-10-01. Phase: **coverage** (CLAUDE.md → «Фаза»). Статус: **проверка готовности пройдена, код не начат** (ROADMAP 3.2). Блокирующие вопросы — раздел «Что нужно решить до кода».
> Источники: `sources/passengers-widget-spec-v1.md` (спецификация, Figma, скриншоты, запись экрана). Общий контекст — `README.md`.

**Principle:** Passengers — справочник по людям в бронировании: кто летит, какого типа, и какие данные по каждому уже введены. Агент сразу видит, чего не хватает (паспорт, дата рождения), и раскрывает карточку только за подробностями. Skydesk показывает факты, а не оценивает бронирование.

## Job

Агент открыл Booking и хочет понять: сколько пассажиров, какого типа, хватает ли данных для выписки билета. Для перелётов внутри Европы достаточно даты рождения и пола, для международных нужен паспорт — поэтому индикаторы на свёрнутой карточке, а полные данные — по кнопке.

## Decided

Из источников (спецификация и скриншоты пользователя, Figma, запись production):

- **Карточка на пассажира**, список в порядке PNR (`P1`, `P2`…). Бейдж `P1` — тот же `RefBadge` (orange), что в матрице Overview; при наведении подсказка «Passenger 1» (Figma `2697:190073`).
- **Свёрнутая карточка:** строка имени (`P1 Landen Marie-louise Ms`), под ней индикаторы `ADT │ ✓ Date of Birth │ ✗ Passport`, справа `Show more ⌄`.
- **Развёрнутая:** под пунктирной линией сетка 3×2 (Date of birth, Gender, Nationality / Passport or ID number, Country of issue, Date of expiration), значения — `IBM Plex Mono`, заглавными; пустое значение — `-`. Дальше блок «Frequent flyer» — **только если есть хотя бы одна карта** (скрывается целиком, это закрывает вопрос 4 из Figma).
- **Тип пассажира всегда виден** (первый элемент строки индикаторов), в любом состоянии данных.
- **Логика индикаторов** (Figma `2294:505086`; функция в `src/lib/`, с тестами):

| Дата рождения | Паспорт | Frequent flyer | Показываем |
|---|---|---|---|
| есть | нет | есть | `✓ Date of Birth │ ✗ Passport │ ✓ Frequent flyer` |
| есть | нет | нет | `✓ Date of Birth │ ✗ Passport` |
| — (не показывается) | есть | есть | `✓ Passport │ ✓ Frequent flyer` |
| — (не показывается) | есть | нет | `✓ Passport` |
| нет | нет | нет | `✗ Date of Birth │ ✗ Passport` |

  Правило: **индикатор даты рождения показывается, только если паспорта нет** (дата уже есть в паспорте). Индикатор Frequent flyer — только положительный (✓), при отсутствии карт скрыт. Паспорт — всегда, ✓ или ✗. Check — зелёный, X — серый.
- **Взаимодействие** (скриншот 4 и запись, источник выше спецификации): кликабельна и фокусируется **вся верхняя строка карточки**, не только `Show more`; карточки раскрываются независимо (можно открыть несколько); содержимое остаётся в DOM при сворачивании; кнопка с `aria-expanded`. Фокус — тёмное кольцо `shadow-focus-ring`, как у других кнопок.
- **Счётчик виджета** (`WidgetSection`, иконка пассажиров) = число пассажиров; тот же, что в шапке Booking («5 passengers») и в левой рейке production.
- **Титул без точки** (`Mr`, `Mrs`, `Ms`, `Dr`), в стиле «первая буква заглавная», серый, рядом с именем.
- **Дата — `DD/MM/YYYY`**, как в шапке бронирования и в Figma.
- **Один Booking — источник** (README): виджет получает `Booking` и выводит свои карточки; своих данных не хранит.

## Данные

Сейчас `Passenger` = `{ ref, type, name }` (`src/lib/booking.ts`). Для виджета нужно (предложение; уточнится после ответов #30–#38):

```
Passenger {
  ref, type, name                       // как сейчас; name — GDS-формат 'LANDEN/ANDERS ROLF BJORN MR'
  title?                                // 'Mr' — если выносим из name
  dateOfBirth?: ISO date
  gender?: 'MALE' | 'FEMALE' | 'UNKNOWN'
  nationality?: string
  document?: { number?, countryOfIssue?, expiresOn? }   // Passport or ID
  frequentFlyers?: { number, airline }[]
}
```

Все поля, кроме `ref`/`type`/`name`, необязательны: пустое — это состояние, а не ошибка. `Overview` и остальные виджеты читают только `ref`/`type`/`name`, существующие mock-сценарии не ломаются.

Доменные правила — `src/lib/passenger.ts` (чистые функции + тесты): `passengerIndicators(p)` по таблице выше, `displayName(p)`, `hasPassport(p)`, форматирование даты. Виджет их вызывает.

## Состояния и как их открыть

Адрес — как у Overview: `?page=booking-overview&pnr=<PNR>`; сценарии добавятся в панель «Booking». Нужные состояния:

| Состояние | Что показывает | Сценарий |
|---|---|---|
| 1 пассажир | счётчик 1, одна карточка | существующий `K2M9QP` + данные |
| 5 пассажиров, все ADT, без паспортов | `✓ Date of Birth │ ✗ Passport`; развёрнутый пустой паспорт — прочерки | новый (по скриншотам 1–2) |
| CHD с паспортом | `CHD │ ✓ Passport`, без индикатора даты рождения, полные данные | новый (по скриншотам 3–4) |
| Паспорт и Frequent flyer | `✓ Passport │ ✓ Frequent flyer`; блок FF в развёрнутой | новый (по Figma) |
| Нет ничего | `✗ Date of Birth │ ✗ Passport`, все прочерки, нет блока FF | новый |
| Несколько FF | три карты через разделители | новый |
| Длинное имя / много FF | перенос, не ломает строку | новый |
| INF / INS | зависит от #30 | после ответа |
| Раскрыто несколько карточек | независимо | любой сценарий |
| Фокус, hover, подсказка бейджа | Tab по карточкам, подсказка «Passenger N» | stories |

Storybook: `Skydesk / Passenger Card` (Collapsed, Expanded, ×состояния данных, Keyboard, Tooltip), `Skydesk / Passengers Widget`. По правилу 10 — JSDoc над `meta`, строка в `docs/components.md`.

## Новые компоненты и зависимости

- `PassengerCard` (`skydesk/passengers-widget/`) — карточка; `PassengersWidget` — `WidgetSection` + список.
- `RefBadge` с подсказкой «Passenger N»: в коде сейчас нативный `title`; в Figma — `Tooltip` из shadcn (`5232:85281`). Нужен примитив `ui/tooltip.tsx` и **новая зависимость `@radix-ui/react-tooltip`** (её в `package.json` нет) — решение пользователя.
- Токен для зелёного check: в `src/tokens/` нет `success`; Figma использует `Success` `#059669` (`emerald-600`). Нужен семантический токен (`extract-tokens`), не палитра в компоненте.
- Пунктирная линия под заголовком карточки — токен или `border-dashed` + `border-border`.

## Not chosen

- Показывать индикатор даты рождения всегда: дублирует паспорт, шумит (спецификация).
- Accordion «только одна карточка открыта»: на записи раскрыто несколько.
- Оценивать полноту данных цветом или текстом «не хватает паспорта»: Skydesk показывает факты (README, принцип).

## Known gaps

- Всё: виджет не построен; данных пассажира в модели нет.
- Левая рейка с теми же счётчиками (open question #26): теперь известно, что её счётчики равны счётчикам виджетов (запись production); что делает клик — неизвестно.
- FOID (#34), INF / INS (#30), Pressed / Hover карточки целиком (в Figma только hover бейджа).
